# 变异算子

变异是探索一个模式的机制。它们刻意是**人工策划的数据**，而不是可执行插件：每个算子都是一条声明式记录，由变异引擎解释执行，因此新增算子不可能引入代码执行。

## 类别与数量

通过统计 `data/creative_operators/*.json` 中的条目核对：

| 文件 | 算子数 | 关注点 |
|---|---|---|
| `rhythm_mutation.json` | 8 | Groove、细分、切分、欧几里得排布 |
| `timbre_mutation.json` | 8 | 音色选择与处理特征 |
| `structure_mutation.json` | 8 | 段落形态、随时间的密度、编配 |
| `pitch_mutation.json` | 4 | 音程、音区、和声色彩 |
| `space_mutation.json` | 4 | 立体声摆位、混响/深度 |
| `constraint_generator.json` | 4 | 约束搜索的规则（「让它遵守 X」这类算子） |
| **变异算子合计** | **36** | |
| `anti_cliche_global.json` | 10 | 把结果推离过度使用素材的全局规则 |
| `cross_domain_mapping.json` | 5 | 跨域意象 → 音乐参数 |

## 算子记录结构

每个算子都带有足够的上下文，既能被应用*也*能被解释：

| 字段 | 用途 |
|---|---|
| 标识 / 名称 | 它如何被选中与报告 |
| `risk`（1–5） | 它离源素材有多远——面向用户警告的依据 |
| `intensityRange`（[1,5]） | 该算子适合哪些强度层级，因此潜行段落不会被配上战斗规模的姿态 |
| `repair` | 反向或修正性的动作，因此一次变异在概念上可以被撤销，而不只是通过版本树 |
| `strudelHints` | 用于实现该算子的具体 Strudel 惯用法，使输出停留在目标语言里，而不是散文 |

`risk` 与 `intensityRange` 正是让变异可用的字段：用户可以要求「给低强度段落一个高风险的想法」，并得到有意义的东西，而不是噪声。

## 跨域映射的思路

`cross_domain_mapping.json` 把非音乐意象转换为音乐参数。经典例子：*「通风系统」* → *缓慢幅度调制的低通噪声*。之所以需要它，是因为让语言模型做「像通风系统那样的东西」，它会产出形容词，而一个映射产出的参数是模式真正能用的。

## 反陈词滥调规则

`anti_cliche_global.json` 中有 10 条全局规则，用来抵消模型趋向泛化素材的倾向。它们是全局的而不是按类别的，因为陈词滥调是整个输出的属性——一个模式可以在节奏上很新鲜，却听起来仍像其他每一个「dark techno」循环。

## 作用域限定在层上

算子从不施加到「整个模式」上。引擎会：

1. 把模式解析成具名层，
2. 校验请求的目标集合与锁定集合（未知名称与重叠都是错误），
3. 只重新生成被瞄准的层的代码，
4. 把结果交回校验器，由它重新检查整个模式。

这就是为什么一次变异可以被信任不会扰动用户喜欢的编配部分——这个不变量由代码强制执行，而不是在提示词里请求。

## 诚实的范围

- 该目录是**手工编写**的；它是人工策划的知识，而不是从数据中学到的。
- 算子的*质量*是音乐判断，不是仓库会去测量的东西。没有任何评估测试架会给「变异是否好听」打分。
- 这 36 个算子是一套可用的词汇，而不是穷尽性的；让它可扩展的是记录结构本身。
